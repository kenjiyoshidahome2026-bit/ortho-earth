# Ortho Earth

> Equal to all, fair to the Earth. This is the project for all people on the earth. The earth is round.

One true-scale Earth, for people and their AI agents. Ortho Earth reads the open data of the Earth in your own browser — on a round globe, at true scale, with no server, no account and no install. A map engine built from scratch (WebGPU with a WebGL2 fallback) draws government vector tiles straight onto the sphere, lifts real terrain, and raises 3D cities as you zoom in. Big data is drawn from GeoParquet, the intelligence layer (identify, topology, choropleths) is Gint, and nothing is exaggerated (terrain at real scale).

## Made to work with AI agents

Ortho Earth is meant to be a map that AI coding agents can use well. What that means in practice:

- An agent already knows how to write it. The globe speaks the MapLibre GL JS and CesiumJS APIs that agents learned from years of public code, and every official example of both is graded on the globe (numbers above), so code an agent writes from memory runs.
- One request is enough. [Build with Ortho Earth](https://www.ortho-earth.com/start.md) is a recipe written for people and agents; every step is run by an automated test against the published npm packages, and an agent given only a one-paragraph request built and verified a working globe page on its first run. It ends with notes for agents (what to install, how to check the page works: `[boot] frame1 received` in the console).
- Nothing to sign up for. No API key, no account, no tile server: public data is read by the browser, so an agent can finish without asking you for credentials.
- The map says what it can do. `map.supports(key)` and `map.capabilities()` report what is built in, what a plugin adds and what is only accepted as a spec, so an agent can check instead of guessing. The packages ship TypeScript types (`globe.d.ts`, `maplibre.d.ts`).
- Current facts in one fetch. This file, [llms-full.txt](https://www.ortho-earth.com/llms-full.txt) and [facts.json](https://www.ortho-earth.com/facts.json) are rebuilt from the source at every deploy, so the version and the compatibility numbers are never older than the site.
- Built that way, too. The developer wrote no code by hand: design and judgement are his, implementation and verification were done with an AI ([the story](https://www.ortho-earth.com/docs/introduction), Japanese).

## How it compares

Written by the developer of Ortho Earth, who has tried to say where the other engines are stronger. The articles below give the conditions and versions; the raw data of the benchmarks is public.

- Different starting points. MapLibre GL JS grew out of 2D cartography and is the strongest for expressive 2D maps. CesiumJS grew out of a 3D Earth with time; 3D Tiles came from Cesium, and it has the longest experience with them. TerriaJS is a finished data-viewing app built on Cesium. Navara pairs a Rust/WebAssembly GIS core with three.js rendering. Ortho Earth puts MapLibre's way of writing a map and Cesium's 3D Tiles, terrain and clock on one always-round globe, draws in a worker (OffscreenCanvas), and uses WebGPU first.
- One model of the Earth at every scale. From the whole planet to a street corner, the map is the same sphere seen by one camera; there is no second, flat mode to switch to. So countries keep their true size side by side, the shortest way between two places is drawn as the arc it really is ([great circle vs rhumb line](https://www.ortho-earth.com/globe/arcs)), terrain is never exaggerated, and when a flat world map is wanted it is Equal Earth, which keeps areas true ([how it is drawn](https://www.ortho-earth.com/docs/equal-earth)).
- Compatibility, not a rewrite. MapLibre and CesiumJS code runs on Ortho Earth unchanged, and the score of every official example is published next to the original (numbers above). Where the picture still differs, the gallery says so.
- Speed on phones (2026-11-11, PLATEAU Chiyoda LOD2 buildings, iPhone XS and Galaxy Tab A11+; MapLibre GL JS 6.17.0 + deck.gl 9.4.1, CesiumJS 1.147.0, Navara 0.3.1, Ortho Earth 2.4.1): Navara and Ortho Earth held the 60 fps screen limit in orbit and zoom on both devices, CesiumJS ran at 57/60 fps on the tablet, and MapLibre + deck.gl stayed below 60 fps in orbit. Navara was the steadiest of all. First display varied more with the network than between engines, so it is not ranked. The data set was small; the gain from WebGPU is not measured yet. [Article (Japanese)](https://www.ortho-earth.com/docs/story-benchmark-mobile-jp).
- Speed on desktops (2026-10-20, two Macs and an iPhone 16 Pro, Ortho Earth 2.0.2): every engine held 60 fps while moving except MapLibre + deck.gl on the M1 and the iPhone; first display tied among the leaders. [Article](https://www.ortho-earth.com/docs/story-benchmark).
- Features (2026-10-21, Ortho Earth 2.0.2; compatibility has grown since, see the numbers above): [Web map engines, feature by feature](https://www.ortho-earth.com/docs/story-features).
- Where Ortho Earth is behind. It is young (first commit April 2026) and made by one developer. It alone of these engines is GPL-3.0 (the others are BSD, Apache-2.0 or MIT), so a page that ships it falls under the GPL unless you take the commercial license. There is no native mobile SDK.

## Build with it

- [Build with Ortho Earth](https://www.ortho-earth.com/start.md): Step-by-step recipe for putting the globe in your own page — with Vite (npm `@ortho-earth/globe`) or without a bundler (npm `@ortho-earth/japan`). Written for people and AI coding agents; every step is run by an automated test against the published packages.
- [MapLibre GL JS examples on ortho-earth](https://www.ortho-earth.com/maplibre/): Ortho Earth is MapLibre GL JS compatible — `import * as maplibregl from "@ortho-earth/globe/maplibre"` runs existing MapLibre code on the globe (recipe section A8). The page lists all {{compatibility.maplibre.examples}} official MapLibre GL JS examples running unchanged, each with its source (in the ortho-earth form), how closely it matches MapLibre, and a Run button.
- [MapLibre GL JS code on a 3D globe](https://www.ortho-earth.com/docs/from-maplibre): Change one import and MapLibre GL JS code runs on the globe — what carries over, the {{compatibility.maplibre.examples}} official examples, and what works differently.
- [Coming from CesiumJS](https://www.ortho-earth.com/docs/from-cesium): Keep your CesiumJS code with npm `@ortho-earth/cesium` (CesiumJS 1.146's names, drawn on the globe), or move to the globe's own API — a table of CesiumJS features (3D Tiles, I3S, quantized-mesh terrain, glTF/GLB, the WGS84 ellipsoid, CZML, the clock) and how to write each one, with a live example per row.
- [CesiumJS Sandcastle on ortho-earth](https://www.ortho-earth.com/sandcastle/): CesiumJS's official Sandcastle examples, each run unchanged on real CesiumJS and on the globe and shown side by side; of the {{compatibility.cesium.graded}} compared, {{compatibility.cesium.samePicture}} draw the same picture and {{compatibility.cesium.sameAnswers}} give the same answers.
- [Coming from Leaflet](https://www.ortho-earth.com/docs/from-leaflet): npm `@ortho-earth/leaflet` gives an `L` like Leaflet 1.9's that draws on the globe — what is translated, what is not, and how to check a port.
- [Coming from Google Maps](https://www.ortho-earth.com/docs/from-google-maps): npm `@ortho-earth/gmaps` gives a `google.maps` on the globe with no Google key for the map; with your key, Geocoder, Directions, Places and Street View are relayed to Google.
- [Equal Earth on the GPU](https://www.ortho-earth.com/docs/equal-earth): How the Equal Earth world map is drawn — the projection in the shader, a central meridian that follows the view, and a morph from the globe.

## Formats and libraries

- [GeoPBF](https://www.ortho-earth.com/docs/geopbf): Compact binary format for geometry and an in-browser converter — 18 formats in, 14 out. npm `geopbf` (MIT).
- [Gint](https://www.ortho-earth.com/docs/gint): Shared-edge topology in a GPU-readable form (GPL-3.0-or-later).
- [AltPBF](https://www.ortho-earth.com/docs/altpbf): Elevation tiles in Protocol Buffers. npm `altpbf` (MIT).
- glbconv: GLB → glTF / OBJ / PLY / STL / USDZ / 3D Tiles in the browser. npm `glbconv` (MIT).
- `@ortho-earth/japan`: a 3D globe of Japan for any page with no bundler — GSI vector tiles and PLATEAU buildings in one self-contained bundle (GPL-3.0-or-later).
- geoedit: the GeoPBF editor — shapes edited on the sphere, large files in place. npm `geoedit` (MIT).
- `@ortho-earth/ephem`: planets, Moon and Sun 1800–2050, satellites (SGP4/SDP4) and the shared clock (GPL-3.0-or-later).
- native-bucket: Cloudflare R2/Workers ↔ IndexedDB bridge and cache for heavy binary data (MIT).
- `@ortho-earth/tile-formats`: lazily loaded decoders — MLT vector tiles and LAZ points for COPC (GPL-3.0-or-later).
- Add-ons for the globe: `@ortho-earth/react`, `@ortho-earth/google3d`, `@ortho-earth/ktx2`, `@ortho-earth/splat`, `@ortho-earth/scene`, `@ortho-earth/h3` (GPL-3.0-or-later).

Since 2.0 the libraries are written in TypeScript (strict) and ship their types; upgrading from 1.x: [MIGRATION.md](https://github.com/kenjiyoshidahome2026-bit/ortho-earth/blob/main/MIGRATION.md).
