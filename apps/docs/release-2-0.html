Ortho Earth 2.0 is out

TypeScript, and a tidied public API
2026-10-17 · @ortho-earth/globe · @ortho-earth/core · @ortho-earth/japan · geopbf

The globe map engine @ortho-earth/globe and the packages around it are now 2.0. 2.0 is the major version that comes with moving the libraries to TypeScript: it removes the aliases, old entry points and internal paths that 1.x kept for compatibility. Drawing and most of the API are the same as in 1.x, and a lot of code runs with the same imports.

1. What changed

  • The source is TypeScript (strict). Types are generated from the source. Where the hand-written 1.x types and the code disagreed (names in the types but not in the code, or the other way round), they now follow the code. Imports are written the same way.
  • Only named entry points. 1.x let you import any file under src/; 2.0 exports only the subpaths listed in each package's package.json exports. internal/* is closed.
  • The 1.x aliases are gone. plateau is now mesh, maxPitch is always in degrees (as in MapLibre), addCOPC is addPointCloud. Your own gadgets are registered with map.registry.gadgets.add(name, (map, ...args) => handle) and receive the map as the first argument.
  • New packages. React components @ortho-earth/react, Google photorealistic 3D Tiles @ortho-earth/google-tiles, KTX2 textures @ortho-earth/ktx2, instanced meshes, billboards and 3D text @ortho-earth/plugin-scene and Gaussian splats @ortho-earth/plugin-splat are published for the first time.

2. Install

npm i @ortho-earth/globe

latest is 2.0. Get started shows your first map; moving code over from MapLibre GL JS or CesiumJS is covered in From MapLibre and From CesiumJS.

3. Moving from 1.x, or staying on it

Everything that needs rewriting is listed per package as "1.x → 2.0" tables in MIGRATION.md (in Japanese; the tables are code and read as they are). APIs not in the tables are unchanged.

Staying on 1.x

Use a version range: npm i @ortho-earth/globe@1 (or geopbf@1). The 1.x source stays on the GitHub branch v1. So that shared URLs and QR codes keep working, 2.0 still reads the old URL forms (the romaji l= keys, lang=jp and so on).

4. Fixes up to 2.0.2

Since 2.0.0 we have been fixing what turned up in use. The main fixes in 2.0.2 (2026-10-19):

  • b3dm 3D Tiles now draw when the worker runs with @loaders.gl 4.5.
  • Maps that turn off the world fills or the elevation index no longer fetch them.
  • Redraws at start-up are batched, 3D Tiles appear once sibling tiles are ready, and the render worker no longer spins when idle.

An article comparing how fast 3D buildings appear in MapLibre GL JS (deck.gl), CesiumJS, Navara and TerriaJS under the same conditions is on the way. It will be added to the article list.
