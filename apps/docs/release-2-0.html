Ortho Earth 2.0 is out

Dropping the old entry points, rebuilt in TypeScript
2026-10-17 · @ortho-earth/globe · @ortho-earth/core · @ortho-earth/japan · geopbf

The globe map engine @ortho-earth/globe and the packages around it are now 2.0. On screen, almost nothing has changed. The Earth turns as before, and a lot of code runs with the same imports. What changed is underneath: the whole source moved to TypeScript, and we took the chance to remove the old names and back doors that 1.x kept "just in case".

This workshop has a rule: when you move to a new idea, throw the old one away. Keeping a compatibility alias hurts nobody. But every alias you keep adds one more "which way should I write this?". 2.0 is the version that clears those questions away.

1. What changed

  • The source is TypeScript (strict). Types are generated from the source. Moving it over turned up more mismatches between the hand-written 1.x types and the real code than we expected: names in the types but not in the code, and the other way round. All of them now follow the code. Imports are written the same way.
  • Only named entry points. 1.x let you import any file under src/. Handy, but every change inside risked breaking someone's code. 2.0 exports only the subpaths listed in each package's exports, and internal/* is closed.
  • The old names are gone. plateau is now mesh, maxPitch is always in degrees (as in MapLibre), addCOPC is addPointCloud. Your own gadgets are registered with map.registry.gadgets.add(name, (map, ...args) => handle) and receive the map as the first argument, so there is no more guessing what this is.
  • New packages. React components @ortho-earth/react, Google photorealistic 3D Tiles @ortho-earth/google-tiles, KTX2 textures @ortho-earth/ktx2, instanced meshes, billboards and 3D text @ortho-earth/plugin-scene and Gaussian splats @ortho-earth/plugin-splat are published for the first time.

2. Install

npm i @ortho-earth/globe

latest is 2.0. Get started shows your first map; moving code over from MapLibre GL JS or CesiumJS is covered in From MapLibre and From CesiumJS.

3. Moving from 1.x, or staying on it

Everything that needs rewriting is listed per package as "1.x → 2.0" tables in MIGRATION.md (in Japanese; the tables are code and read as they are). APIs not in the tables are unchanged.

Staying on 1.x

Use a version range: npm i @ortho-earth/globe@1 (or geopbf@1). The 1.x source stays on the GitHub branch v1. We threw away the old entry points in the code, but not the URLs we handed out: 2.0 still reads the old URL forms (the romaji l= keys, lang=jp and so on). A map once given to someone should keep working.

4. What we found after the release

To be honest, 2.0.0 needed fixes after it went out. Most of them came from a performance measurement: showing PLATEAU 3D buildings in MapLibre GL JS (deck.gl), CesiumJS, Navara and TerriaJS under the same conditions. Measured side by side with other engines, habits we never noticed on our own turn into numbers. 2.0.2 (2026-10-19) fixed these:

  • With @loaders.gl 4.5 in the worker, b3dm 3D Tiles did not draw. Building the comparison pages showed that ortho-earth was the only engine that could not draw the buildings with this combination.
  • Maps that turned off the world fills or the elevation index still fetched them. Now what is not used is not fetched.
  • Redraws at start-up are batched, 3D Tiles appear once sibling tiles are ready, and the render worker no longer spins when idle.

The measurement itself was fun. The same "60 fps" means very different things in each engine: some stop loading tiles while the camera moves to stay smooth, some draw a coarser picture on phones, some keep loading as they draw. Where each one cuts corners says a lot about how it was designed. The details will be a separate article, added to the article list when it is out.
