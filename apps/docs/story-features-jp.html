五つの Web 地図エンジンの機能比較：MapLibre・Cesium・TerriaJS・Navara・ortho-earth

2026-10-21 · Kenji Yoshida

はじめに

先の記事では、PLATEAU の建物を五つのエンジンで描いて速さを比べました。今回はその対として、何ができるかを比べます。ベンチで使った版の資料とソースを読んで確かめました。MapLibre GL JS 6.15.0（と deck.gl 9.4）、CesiumJS 1.146、TerriaJS 8.13.0（中の Cesium は 1.142 相当）、Navara（@navaramap/three 0.2.1）、ortho-earth（@ortho-earth/globe 2.0.2）です。

今回も先に断っておくと、私は ortho-earth の開発者です。他のエンジンの強いところは強いと、ortho-earth の足りないところは足りないと書くようにしました。

結論：出発点が違う

五つは同じ「地図エンジン」と呼ばれても、出発点が違います。MapLibre は 2D の地図表現（ベクトルタイルと注記）から、Cesium は 3D の地球と時間から生まれました。Terria は Cesium の上に作ったデータ閲覧の完成品、Navara は Rust の GIS の中核と three.js の写実的な描画の組み合わせ、ortho-earth は「いつも球」の地球儀に MapLibre の API を載せたものです。

だから機能の多い少ないで一列には並びません。2D の地図の表現力なら MapLibre、3D Tiles と時間で変わるデータの厚みなら Cesium、データを集めて見せる道具一式なら Terria、写実的な絵作りなら Navara が一番強いと思います。ortho-earth は、MapLibre の書き方と Cesium の 3D・時計を一つの球の上にそろえ、描画を worker に出している、という組み合わせが他に無いところです。

図法：どこまでが球か

いちばん根の深い違いは図法にあります。MapLibre の globe は、style の projection を "globe" にすると、低いズームでは球で描き、寄るにつれて Mercator へ移っていく作りです。中身は Mercator の地図で、球は遠くから見たときの見え方として後から足された、という順序が読み取れます。逆に Cesium は最初から WGS84 楕円体の 3D で、2D と Columbus view は 3D の場面を変形して作ります。Terria は 3D を Cesium、2D を Leaflet と、別のエンジンを切り替えて持っています。

Navara と ortho-earth は球しか持ちません。ortho-earth は「Mercator の画面に切り替えられない」ことを意図して書いていて、MapLibre の projection も何を書いても globe として読みます。平らな世界図が要るときは Equal Earth（正積）を別に持ち、地球儀から開く変形でつないでいます。Web Mercator の平面を一度も通らないのは、五つの中で ortho-earth だけです。

スレッド：どこで描くか

性能の比較で見えた「空いたメインスレッド」は、ここの違いから来ています。MapLibre と Cesium はタイルの解読や幾何の生成を worker に出しますが、描画そのものはメインスレッドで行います。Terria はその上に React の UI が同じスレッドで走ります。Navara は Rust の中核（Bevy ECS）を WebAssembly で動かし、地形のメッシュ作りなど重い処理を worker に出しますが、毎フレームの ECS の更新と three.js の描画はメインスレッドにあります。

ortho-earth は地図を描画 worker の OffscreenCanvas に描きます。メインスレッドに残るのは入力と UI と注記の重ね描きくらいです。そのかわり、deck.gl の interleaved（同じ GL の文脈を分け合う重ね方）は使えず、overlaid に落ちます。three.js や custom layer は URL で渡すと worker の中で同じカメラ・同じ深度で描けますが、オブジェクトを直接渡すとメインスレッドの別の canvas になり、深度を分け合えません。worker で描く利点と引き換えの制約として、正直に書いておきます。

3D データ

3D Tiles の扱いの厚みは Cesium が群を抜いています。1.0 と 1.1 の形式、I3S、点群、Gaussian splat、voxel まで本体で読み、Cesium3DTileStyle と CustomShader で地物ごとに見た目を変えられます。1.142 からは MVT も 3D Tiles に変換して読めるようになり、1.146 では地形や 3D Tiles の上に貼り付けて描けるようになりました。Terria は中身が Cesium なので、この厚みをそのまま受け継いでいます。

MapLibre は本体に 3D Tiles を持たず、ベンチでも deck.gl の Tile3DLayer を重ねました。読めるのは loaders.gl の範囲で、MapLibre の style からは扱えません。Navara は b3dm・pnts・glb を読みますが、i3dm と cmpt はまだ未対応です（ソースに TODO があります）。ortho-earth は b3dm・i3dm・pnts・cmpt・glb と I3S、COPC の点群まで読み、splat は plugin で足します。

ベクトルタイルと注記

2D の地図の表現は MapLibre が本家で、他は皆これにどれだけ寄せるかで測られます。MVT と MLT、式（expression）、SDF の文字、衝突回避、線に沿う注記、右から左へ書く文字の plugin まで揃っています。

ここは五つの差が最も大きいところでもあります。Cesium の MVT は 3D Tiles への変換で、スタイルは MapLibre の style ではなく Cesium3DTileStyle で書きます。注記の LabelCollection には地図のような衝突回避が無く、重なりは EntityCluster でまとめる形です。Terria の MVT は protomaps で画像に焼いて貼るので、文字は地面に描かれた絵になり、傾けると寝ます。Navara は MapLibre style の plugin を持ちますが一部の対応で、glyph PBF を読まず Web フォントで文字を描きます。

ortho-earth は MapLibre の公式の例 139 本で照合していて、同じ絵 70・同じ答え 42・動く 25・動かない 0 です。注記は GL の SDF ではなく Canvas2D の重ね描きで、衝突の判定は間引いて当選を安定させ、位置は毎フレーム投影し直しています。縦書きと 26 言語まで持つのは、日本語の地図から始まったエンジンらしいところだと思います。

時間

時間を第一級に扱うのは Cesium の伝統で、Clock と Timeline、CZML の補間付きの位置、時間で変わる画像まであります。Terria はこれを利用者向けの時間軸にしていて、WMS の時間次元や CSV の時系列をそのまま再生できます。MapLibre には時計が無く、時間はアプリが style を書き換えて表します（deck.gl の TripsLayer は currentTime を持ちます）。Navara の時間は太陽の位置と glTF のアニメーションまでで、データの時計はありません。

ortho-earth は map.clock 一つで、夜の側、星、人工衛星（SGP4）、CZML の補間付きの位置、trips を同じ時刻で動かします。Cesium から来た方に向けた頁でも、Clock と CZML は書き方の対応表に入れてあります。

絵作り

写実的な絵では Navara が一番先へ行っています。大気、雲、カスケード影、SSR（水面の映り込み）、SSAO、被写界深度、bloom、色の LUT まで、three.js の後処理を地球の上で使えます。Cesium は大気・影・PBR・点群の EDL と堅実です。ortho-earth は WebGPU で影・AO・切断面・大気散乱を描き、WebGL2 ではそれを省いた同じ地図になります。MapLibre は 2D の地図の範囲の空・霧・光にとどまります。

完成品か部品か

Terria だけは部品ではなく完成品です。カタログ（WMS・ArcGIS・CKAN・SDMX など 40 種類近い読み口）、作業台、地物情報のテンプレート、画面分割の比較、ストーリー、共有リンク、スマホ用の UI まで最初から揃っています。性能の比較で JS ヒープが Cesium より多かったのはこの上乗せ分で、データを見せる道具として使うなら、その重さに見合う中身があります。Cesium も Viewer に時間軸や地名検索の部品を同梱していますが、他の三つは地図そのものを渡す部品で、UI はアプリが作ります。

使用許諾

組み込む側にとって無視できない違いとして、ortho-earth だけが GPL-3.0 で、他の四つは BSD・Apache・MIT のいずれかです。ortho-earth を組み込んだ頁を配る場合は、その頁のコードも GPL の条件に入ります。比べるなら、ここは一行添えておくのが公平だと思います。

ortho-earth の立ち位置

機能の幅だけを見ると、ortho-earth は MapLibre の 2D の書き方（style、式、queryRenderedFeatures、注記）と、Cesium の 3D と時間（3D Tiles、I3S、quantized-mesh、CZML、時計）の両方に手を伸ばしている点で、五つの中で一番範囲が広いと思います。そこに日影時間・可視域・見通しといった解析も本体に入っています。

ただし、それぞれの本家と比べると、深さはまだ追いかける側です。MapLibre の例は 139 本中 25 本が「動くが絵か答えが違う」で、Cesium の voxel や 3D Tiles のスタイル言語、Terria のカタログのような長年の蓄積はまだありません。worker で描くことによる deck.gl の interleaved の制約と、GPL という許諾も、選ぶ側にとっての条件になります。

性能では Cesium と同じ帯にいて、機能では MapLibre と Cesium の交わりを一つの球の上で取っている。今の ortho-earth を公平に書くと、そうなると思います。
