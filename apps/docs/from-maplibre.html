@ortho-earth/globe/maplibre is the MapLibre GL JS API drawn on the Ortho Earth globe engine (WebGPU with a WebGL2 fallback). Code you wrote for MapLibre keeps working; the map it draws is a round Earth with terrain at true scale, and the same map can also show 3D Tiles, I3S, glTF models and the sky.

1. The one line

import * as maplibregl from "@ortho-earth/globe/maplibre";   // was: from "maplibre-gl"

const map = new maplibregl.Map({
  container: "map",
  style: "https://demotiles.maplibre.org/style.json",
  center: [139.77, 35.68],
  zoom: 4,
});

map.on("load", () => {
  map.addSource("cities", { type: "geojson", data: "cities.geojson" });
  map.addLayer({ id: "cities", type: "circle", source: "cities",
    paint: { "circle-radius": 6, "circle-color": "#e4572e" } });
});

Install with npm i @ortho-earth/globe and build with Vite. Zoom levels follow MapLibre's, so zoom, minzoom/maxzoom and tile levels mean the same as in your code. If you use MapLibre's controls, keep linking maplibre-gl.css. The full recipe, run by an automated test against the published package, is section A8 of Build with Ortho Earth.

2. The 139 official examples

Every official MapLibre GL JS example runs on the globe with its code unchanged — only the import is switched. The MapLibre examples page shows each one with its source, a Run button, and how closely the picture matches MapLibre's. 3. What works differently

  • Always a globe. There is no flat Mercator mode: projection is read as globe whatever it says, and renderWorldCopies has nothing to copy. The flat world map of this project is Equal Earth.
  • Drawing happens in a worker. A custom layer passed as an object is drawn on top of the map; a custom layer with a url runs inside the render worker and is hidden by terrain and buildings. deck.gl's MapboxOverlay works as an overlay (interleaved: true falls back to overlaid).
  • For three.js, use map.addThree({ module }). It draws inside the render worker with the map's camera, is hidden by terrain and buildings, and answers clicks. Your module imports "three" and "three/addons/…" as usual (three.js comes from jsDelivr by default; depth needs r180 or later). With renderer: "webgpu" it uses three's WebGPURenderer and, when the map runs on WebGPU, shares the GPU device and the depth (no per-frame copy). To move a MapLibre custom layer over unchanged, put it in a module and pass url and three (guide: THREE.md in the package).
  • More than MapLibre. The same map takes 3D Tiles (map.add3DTiles), I3S, quantized-mesh terrain, glTF models, a shared clock with the night side and the stars, and analysis such as sun shadow and viewshed. Coming from CesiumJS too? See From CesiumJS.

The ledger of every difference, kept as the work goes on, is packages/globe/maplibre-compat.md in the repository.
