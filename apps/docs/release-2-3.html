Ortho Earth 2.3 is out

Hop, step, jump

2026-11-02 · Kenji Yoshida · @ortho-earth/globe · @ortho-earth/core · @ortho-earth/cesium

@ortho-earth/globe and @ortho-earth/core are now 2.3, together with @ortho-earth/cesium 0.2.0 and @ortho-earth/voxel 0.6.1.

Put side by side, the three releases of the last ten days or so make a hop, a step and a jump.

ReleaseDateWhat it did
Hop　2.1Oct 23The MapLibre release. Map text moved to the GPU; MapLibre official examples with the same picture went from 66 to 79
Step　2.2Oct 31The CesiumJS release. Every graded Sandcastle example runs; same picture went from 23 to 190
Jump　2.3Nov 2One more step toward both, and rendering effects that neither has

At the end of 2.2 I wrote a formula: Ortho Earth = MapLibre × Cesium − Mercator + α. 2.3 tightens the MapLibre and Cesium terms, and is the first release that puts something concrete into the + α.

1. One more step toward CesiumJS

The yardstick is the same as for 2.2: Cesium's own Sandcastle examples. Each runs unchanged on real CesiumJS and on the globe, and two pictures taken at the same time from the same camera are compared. This time 303 are graded, including a few that the sampled picture cannot judge and were checked by eye. Every pair is at /sandcastle.

After 2.2, all 309 examples were re-shot more than 20 times, and each time one family of differences was fixed. This is what went into the engine, all of it usable from the plain globe API too:

  • Imagery split view (ImageryLayer.splitDirection), and imagery tiles as fine as Cesium picks them.
  • 3D Tiles edge visibility (EXT_mesh_primitive_edge_visibility), shadows from translucent 3D Tiles, and 3D lines that stop in front of buildings.
  • Entity shapes lit with Cesium's phong lighting, front and back faces of closed shapes, and shapes clamped to terrain.
  • Globe clipping planes and limit rectangle, and time-dynamic WMTS.

The changes are in the MapLibre-compatible API (@ortho-earth/globe/maplibre). The globe's own API behaves as before.

  • The vertical field of view is MapLibre's 36.87°. The default Mercator constraint, maxZoom 22 and the flyTo and easeTo choreography also follow MapLibre.
  • Unproject on terrain walks the line of sight from near to far and returns the first point where it meets the ground.
  • Terrain exaggeration applies to the centre's height and to queryTerrainElevation too.
  • Custom layers on the globe use MapLibre's axes, so three.js models stand as they do there.

3. + α: new rendering effects

map.setPostChain gains six effects (WebGPU only; on WebGL2 they do nothing). Neither Cesium nor MapLibre has them. 

map.setPostChain([
  { type: "ssr", ocean: 0.5, facades: 0.3 },   // screen-space reflections: sea, wet ground, glass facades
  { type: "contactShadow" },                   // contact shadows on terrain, buildings and models at any zoom
  { type: "heightFog", density: 0.4 },         // height fog: morning mist in the valleys
  { type: "godRays" },                         // light shafts through ridges and between buildings
  { type: "rain", intensity: 0.8 },            // rain: wet ground, puddles, ripples, streaks
  { type: "toon", levels: 4 }                  // an illustration style
]);

They all reuse the depth and normals the engine already had. SSR is about 380 lines and the other five about 720, and each went in within a day. Along with them, a still camera now refines its picture over a few frames (jittered and accumulated).

2.1 and 2.2 rebuilt the inside so the globe could do what two other engines do. On that base a new effect is a small addition. This release was also a check of that.

4. Same API as 2.2

Everything in 2.3 is added on top. Code written for 2.2 runs on 2.3 as it is. There is one visible change: an ssr pass in setPostChain used to be stored only, and on WebGPU it now draws (the sea reflects by default). @ortho-earth/cesium 0.2.0 needs @ortho-earth/globe 2.3 or later. 

npm i @ortho-earth/globe@2.3
npm i @ortho-earth/cesium      # CesiumJS code

The detailed record of these three days is in "V.2.3.0 Between two gods".

Looking back, the term in that formula that mattered most may have been − Mercator. Because the map was drawn on a sphere from the start, not on a plane, MapLibre's 2D examples and Cesium's 3D examples could both be taken in by one and the same way of drawing. Not building 2D and 3D separately and joining them, but dropping Mercator: I think that was the essence of bringing 2D and 3D together this time.
