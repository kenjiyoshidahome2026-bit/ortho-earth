Ortho Earth 2.3 を公開しました

ホップ・ステップ・ジャンプ

2026-11-02 · Kenji Yoshida · @ortho-earth/globe · @ortho-earth/core · @ortho-earth/cesium

@ortho-earth/globe と @ortho-earth/core を 2.3 にしました。あわせて @ortho-earth/cesium 0.2.0 と @ortho-earth/voxel 0.6.1 も出します。

この十日あまりの三つの版を並べると、ちょうどホップ・ステップ・ジャンプになりました。

版日付したこと
ホップ　2.110 月 23 日MapLibre の版。地図の文字を GPU に移し、MapLibre の公式例で同じ絵が 66 本から 79 本に
ステップ　2.210 月 31 日CesiumJS の版。Sandcastle の採点した例がすべて動き、同じ絵が 23 本から 190 本に
ジャンプ　2.311 月 2 日両方にもう一歩近づき、どちらにも無い描画の効果を足した

2.2 の終わりに、Ortho Earth ＝ MapLibre × Cesium − メルカトル ＋ α という式を書きました。2.3 は、その MapLibre と Cesium の項を詰め、＋ α を初めて具体的にした版です。

1. CesiumJS にもう一歩

物差しは 2.2 と同じ、Cesium 公式の Sandcastle です。本物の CesiumJS と地球儀で同じコードを動かし、同じ時刻・同じカメラで撮った二枚の絵を比べます。 今回は、撮った絵では判定できず目で確かめた例も加えて、303 本を採点しています。全部の組は /sandcastle で見られます。

2.2 のあとも全 309 本を 20 回以上撮り直し、そのたびに一つの系統を直しました。エンジンに入ったものは次のとおりで、どれも素の地球儀の API からも使えます。

  • 画像の左右分割（ImageryLayer.splitDirection）と、Cesium と同じ規則で選ぶ画像タイルの細かさ。
  • 3D Tiles の辺の表示（EXT_mesh_primitive_edge_visibility）、半透明の 3D Tiles が落とす影、建物の手前で止まる 3D の線。
  • Entity の形を Cesium の phong の光で描く、閉じた形の表と裏、地形に沿わせた形。
  • 地球のクリッピング面と範囲の矩形、時刻つきの WMTS。

2. MapLibre GL JS にもう一歩

Cesium を追っている間に、もう一つの物差しである MapLibre の公式例 139 本（採点は 137 本）がどう見えるかを測り直しました。本物は MapLibre GL JS 6.11.2 です。 全部の組は /maplibre で見られます。

MapLibre 互換の口（@ortho-earth/globe/maplibre）で変えたのは次のとおりです。地球儀そのものの API の振る舞いは変えていません。

  • 縦の画角を MapLibre と同じ 36.87° に。Mercator の既定の制約、maxZoom 22、flyTo・easeTo の動きも MapLibre に合わせました。
  • 地形の上での unproject は、視線を手前から歩いて最初に地面と交わる所を求めます。
  • 地形の誇張（exaggeration）は、中心の高さと queryTerrainElevation にも掛かります。
  • 地球儀の上の custom layer は MapLibre と同じ軸になり、three.js の模型がそのまま立ちます。

3. ＋ α：新しい描画の効果

map.setPostChain に六つの効果が加わりました（WebGPU だけ。WebGL2 では何もしません）。Cesium にも MapLibre にも無いものです。 

map.setPostChain([
  { type: "ssr", ocean: 0.5, facades: 0.3 },   // 画面空間の映り込み：海・濡れた地面・ガラスの壁
  { type: "contactShadow" },                   // 接触影：どのズームでも地形・建物・模型に
  { type: "heightFog", density: 0.4 },         // 高さ霧：谷の朝霧
  { type: "godRays" },                         // 光芒：尾根や建物の隙間を抜ける光
  { type: "rain", intensity: 0.8 },            // 雨：濡れた地面、水たまり、波紋、雨の筋
  { type: "toon", levels: 4 }                  // イラスト風
]);

どれもエンジンが前から持っていた深度と法線を使い回しています。SSR が約 380 行、残りの五つで約 720 行、それぞれ 1 日で入りました。 あわせて、カメラが止まると数フレームかけて絵を仕上げる（ジッタを掛けて重ねる）ようにしました。

2.1 と 2.2 で、他の二つのエンジンと同じことができるように中を作り直してきました。その土台の上でなら、新しい描画は小さな足し算で済みます。今回はそれを確かめた版でもあります。

4. 使い方は 2.2 のまま

2.3 はすべて上に足した物です。2.2 向けに書いたコードは 2.3 でそのまま動きます。 目に見える変化が一つあります。これまで setPostChain の ssr は受け取って保持するだけでしたが、WebGPU では描かれるようになりました（既定で海が映ります）。 @ortho-earth/cesium 0.2.0 は @ortho-earth/globe 2.3 以上が要ります。 

npm i @ortho-earth/globe@2.3
npm i @ortho-earth/cesium      # CesiumJS のコード

この三日間の詳しい記録は「V.2.3.0 二柱の神のあいだで」に書きました。

振り返ると、あの式でいちばん効いていたのは「− メルカトル」だったのかもしれません。地図を最初から平面ではなく球の上に描いてきたので、MapLibre の 2D の例も、Cesium の 3D の例も、同じ一つの描き方で受け止められました。 2D と 3D を別々に作ってつなぐのではなく、メルカトルを捨てたこと。それが今回の 2D と 3D の統合の本質だったと思います。
