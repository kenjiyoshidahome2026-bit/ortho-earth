# 描画側 LOD と tiler の DP 較正（geopbf 改良点 12）— 計測と判断 2026-10-12

俯瞰（2026-10-04）の改良点 12「描画側 LOD を tiler と同じ DP 較正に（`calibrate.js` の弧ごとの閾値表を描画の uniform に流す）★」を、
組む前に**どれだけ揃うか・何が要るか**を実データで測った。物差しは `scripts/lod-calibration-report.mjs`（常設検定 `tests/t-lod-calibration.mjs`）。

## 今の仕組み
- 描画（ortho-core `gl/gint/drawdata.js:66-89`）: 1px が覆う地表面積から VW rank の閾値を出し（固定則 `rank ≥ 63 − 3z` と同系）、VS の `lodSnap` が閾値未満の頂点を捨てる。閾値は**層で 1 つ**（uniform `u_lod_rank`／`F.lodRank`）。
- tiler（`convert/calibrate.js`）: arc ごとに Douglas–Peucker の予算（tippecanoe `-S`＝弦から 1 タイル単位）を数え、「残る数が DP に最も近い」rank 閾値 `t(arc, z)` を表にする（`Uint8Array(zoomCount × arcCount)`）。頂点の選び方は VW のまま＝共有境界は両側で同じ。

描画をこの表に揃えるには、VS が **頂点 → arc** を引く表（arc 数 < 65,536 なら u16・それ以上は u32 ＝ arcTex 8 bytes/頂点に対し +25〜50%）と、層ごとの `t` 表（arc 数 × ズーム数 bytes）と、2 バックエンド（GLSL／WGSL）× 線・pick・stencil・ID 塗りの各パスの `lodSnap` の変更が要る。
「arc ごとの定数オフセット（1 byte/頂点）」で済むなら安いので、それも測った。

## 物差し
各戦略が DP の予算 `want(arc, z)`（DP が残す頂点数）にどれだけ近いか＝ `Σ|kept − want| / Σwant`（kept 集合の L1 誤差・小さいほど DP に近い）。
- `fixed`＝描画の固定則 `63 − 3(z + log2(4096/256))`（tiler の固定則と同じ尺・描画の 1px ＝ タイル z−4 の 1 単位）
- `constD`＝arc ごとの定数オフセット（DP が全部を欲しがらないズームでの `t − fixed` の平均）
- `lin`＝ズームに線形のオフセット（2 bytes/頂点案）
- `table`＝tiler の表 `t(arc, z)` そのもの

## 読み
1. **固定則は、データの解像度が効くズーム帯では DP とほぼ同じ密度**（pop-density: z0〜2 で 1〜8%、z6 以上は 0〜1%）。差が出るのは z3〜5 の帯だけで、最大でも固定則が 13% 多く残す（z4: 52,580 対 46,542）。
2. **arc ごとの定数オフセットでは較正できない**（constD は固定則より悪い）。VW と DP の差は「arc の形」ではなく「ズームごとの頂点間隔と弦の関係」で、ズームと共に変わる＝1 byte/頂点の近道は無い。線形でも足りない。
3. **表そのものを流せば揃う**（pop-density で 0〜4%）。ただし低解像度データ（countries）は表でも 38% 残る＝rank の粒度（arc あたり数頂点）の限界で、tiler も同じ。
4. 費用: 頂点 → arc の表（+25〜50% の GPU メモリ・N03 級 1,000 万頂点で +20〜40 MB）、層ごとの `t` 表、較正（CPU・20k arc で 44 ms＝bake worker で N03 級なら数秒）、2 バックエンド × 4 パスの VS 変更。描画の閾値は連続（pxArea 由来）なので表の行間の補間も要る。

## 判断
**今回は組まない（保留）。** 得られる差が「z3〜5 の帯で頂点が 1 割前後」で、MapLibre（tippecanoe 既定）との見た目の差としては線の密度がわずかに濃い側に寄るだけ。
対して費用は全 gint 層の GPU メモリ +25〜50% と全パスの VS 変更＝実 GPU での検証無しに入れる変更ではない。
やるなら「頂点 → arc の u16 表（arc < 65k の層だけ）＋ `t` 表を R8UI テクスチャ・`lodSnap` が `t[arc][floor(zf)]` と `t[arc][ceil(zf)]` の間を補間」の形で、
手元 Mac の実 GPU で `/japan/` の市区町村（この pop-density と同じ台帳）を z3〜5 で見比べてから決める。物差しは残す（`npm test` の t-lod-calibration が calibrate.js の退行も止める）。
